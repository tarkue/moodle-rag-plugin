# INZHE Knowledge theme

Native Boost child theme for Moodle 4.5 LTS. Install as `theme/inzhe`, run Moodle's plugin upgrade, select **INZHE Knowledge** in the theme selector and purge caches. It inherits maintained Boost layouts, navigation, course activities, authentication and accessibility. No Klass theme, browser extension, remote font or JavaScript injection is required.

The palette follows the supplied knowledge-base and chat PNGs: teal `#008292`, dark teal `#006f7d`, ink `#1e1e1e`, muted `#797979`, soft surface `#f4f4f4`. Inter Variable is bundled locally from the official rsms/inter repository under its included OFL license, with Arial fallback. The genuine logo comes from the public asset URL in the user-supplied original CSS. Native Boost navbar and footer partials retain Moodle user/edit/mobile controls while applying the provided identity.

## Native knowledge-base activity

The theme styles the standard Moodle Database activity and keeps its real search, filters, permissions, pagination and file handling. For the card view create fields named `Название` (text), `Автор` (text), `Год` (number), `Теги` (text), `Файл` (file) and `Обложка` (picture), then use the files under `dbtemplates/` as its list header, repeated entry, footer and advanced search template. The advanced template presents the four supported title/author/year/tag filters; add native field placeholders when extending the catalogue. Map listheader.html to Moodle `listtemplateheader`, and listfooter.html to `listtemplatefooter`. Populate only actual documents. Moodle emits the authorized original file links and edit controls. Using the theme never changes document permissions.

The RAG panel is supplied separately by `block_ragchat`, injected by `local_rag` after server-side configuration and access checks. Its JavaScript requires only the Moodle session key and proxy URL, never a service or administrator token. Without service configuration, `local_rag` must omit its shell and bootstrap.

The presentation-only catalogue AMD module splits tag text into escaped individual chips and localizes native search submit labels. It preserves native form DOM, field names, submission and reset. The generic portrait cover is an honest fallback for documents without an uploaded cover.

## Frontend check

`node --test blocks/ragchat/tests/chat_test.cjs` (from the plugin root) checks input limits, safe source-link protocols and disabled bootstrap. The committed AMD build is a named production RequireJS module generated by `node blocks/ragchat/build.cjs`; it has no external npm dependency.

Run `node theme/inzhe/build.cjs` after editing the catalogue module, then purge Moodle caches. The committed named AMD build has no external npm dependency.
